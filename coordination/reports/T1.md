## Graph rules and defaults
- Lines are split at vertices shared by two lines (switches); crossings without a shared vertex (bridges) stay unconnected. Both directions, lengths geodesic (WGS84).
- Excluded by default: `service=yard|siding|spur` (`include_service=True` brings them in); `crossover` stays. Other `railway` values dropped and counted.
- No "largest component" restriction on snapping (a tram and a main line in one bbox are disjoint); unreachable pairs raise `no rail route`.
- Speed = `maxspeed` else class default: rail/usage=main 120, branch 80, industrial/military/tourism 40, untagged rail 80, light_rail 70, subway 70, tram 40 km/h.
  **Every default is an assumption (`assumption: true`).** The module cites Norwegian mainline 100-130 km/h (Bane NOR / Norske tog), T-bane 70, tram 40 as reference
  points from memory; they were NOT verified (banenor.no unreachable here). Do not quote them as sourced.
- Stations: `snap_stations` returns station, ref, node lon/lat, `snap_m`, `snapped`; beyond `max_snap_m` (500) -> `snapped=False`, or raise with `strict=True`.

## What the hook changes for a train trip
Before: a rail/tram trip with no shapes.txt ran in straight lines between stops. Now the order per trip is shapes.txt, rail graph, straight.
With a rail graph the stops are snapped onto the track (distance in `meta["rail_snap_m_max"]`), the path follows the track between consecutive stops
(reversals included), and along-track distance replaces straight distance, so `vehicle_km` and `vmax` follow the track. Timetable times are untouched.
Per trip source in `meta["geometry_by_trip"]` (`shapes|rail_graph|straight`), counts in `meta["geometry"]`, failures in `meta["rail_fallback"]` with reasons.
`rail="auto"` reads `<world>/osm/rail.geojson` beside the GTFS folder, so the unchanged `gtfs` engine picks it up (it lands in `meta["dropped"]` because the engine
passes the build stats through under that key). No agents/contract columns, KPIs or engine code changed. Worlds without a rail layer behave exactly as before.

## Not built (scope the next package from this)
- Single-track capacity, crossing/passing loops and conflict resolution; headway and block-section occupancy.
- Signalling and interlocking (ERTMS/ATC), speed profiles, acceleration/braking, gradient and curve speeds, switch speed limits.
- Platform occupancy and track allocation at stations; dwell-time models (the timetable dwell is replayed as given).
- Electrification as a constraint and energy use (the tag is read and kept, never used); battery/hydrogen trains; regenerative braking.
- Freight paths and slots, terminals, wagon and train composition, axle-load and loading-gauge limits.
- Bane NOR network statement / capacity allocation data, line-by-line speed and possession data (needs a real source; OSM maxspeed is patchy).
- Delays, real-time (Entur SIRI), disruptions; frequencies.txt expansion.
- Directionality on double track, ferry/rail intermodal links, GTFS `parent_station` mapping to station nodes (stops are snapped by coordinates, not matched by station id).
- Engine-side: `extra["gtfs"]` has no `rail` key; only the default "auto" path is reachable through the engine. Forwarding `rail` needs a one-line engine change (not in this package).

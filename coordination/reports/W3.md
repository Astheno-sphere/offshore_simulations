## What it does
- `codes.py`: 22 codes (`CODES[code] = (gate, meaning)`), `classify(report | gate entry | qa dict | text | exception)`, `code_for_gate`.
  Reads the `code` field first; old reports fall back to gate name + detail text. Contract kinds: speed, teleport, land, capacity,
  state -> G3-*; `time` -> G3-STATE (bookkeeping); `schema` -> DATA-SCHEMA. Multiple kinds: first violation in the text wins.
- pipeline: `stop()` writes `code` into the failing gate entry and `report["code"]`; a gate 4 that ends "did not reproduce" gets
  G4-KPI-MISMATCH. Passing runs and "not comparable" runs are byte-identical to before (no code); existing keys untouched.
  Engine `Unsupported` is not always "class unsupported": it is routed by message (not installed -> TOOL-UNAVAILABLE, handles/got ->
  TOOL-MISMATCH, no weather -> DATA-MISSING, malformed weather -> DATA-SCHEMA, demand exceeds capacity at gate 1 -> PLAN-INFEASIBLE).
- Playbooks: symptoms, checks (functions in `checks.py`, `{ok, evidence}`; ok True = nothing wrong, False = cause found, None = could not run),
  repairs `[{id, kind, action, why_safe}]` (+ `op` on auto), question. Auto ops are a closed vocabulary `doctor.AUTO_OPS`:
  report_command, pull_world, rerun_gate, rerun_seed (G1, G1B only), clear_partial_downloads. Everything touching a sourced value,
  assumption, tolerance, tool choice or code is `human`.
- `diagnose(report | path | paper_id | text)` -> `{code, gate, meaning, detail, checks, repairs, question, ok, fix_command}`.
  `repair(report_path, max_attempts=2, run=False, runner=None)`: run=False only plans; run=True executes auto repairs, each followed by a rerun
  of the same scenario into `<report dir>/repair-N/` (failing report kept), re-diagnoses, stops when the gate passes; max_attempts counts
  reruns. Always writes `diagnosis.json` next to the report. A crashing check is reported as ok=None, not as a pass.
- `cli.main(argv) -> int` (for W2): argv may start with `doctor` or `learn`, or omit it (`--code/--symptom` => learn, else doctor).
  `doctor <report.json|paper_id|text> [--repair [--dry-run]] [--max-attempts N] [--json]`. Note `--repair` EXECUTES auto repairs;
  `--dry-run` plans. Exit 0 = passes/resolved, 1 = failure remains, 2 = refused/not found.
  `learn --code C --symptom S --cause X --fix F --guard G [--open]`: guard must exist (test function found in file, or
  `playbook:CODE::check` listed in the playbook and defined in checks.py); otherwise refused (exit 2) unless `--open`. Regenerates docs/LESSONS.md.
- Lessons seeded (9 closed, 2 open): PyVRP offsets/is_client (guard playbook check pyvrp_only_via_adapter), straight legs over land

## Order matters. Do them in this order.

### N4.1 — the weather fetch (highest value, unblocks every reportable run)

Every paper run today uses `weather: {synthetic: ...}` and is stamped "not reportable", so
`offsim article` refuses it. That is correct behaviour and it is also a ceiling on the whole project.

A new resumable backend landed on main (package A3, `offsim/worlds/metocean_api.py`). It fetches one
subprocess per product-month, 144 units for 24 winters, kills a unit after 600 s, writes atomically, and on
restart skips what is already on disk and valid. The previous attempt died at 5 of 24 winters because a
SIGALRM budget cannot interrupt netCDF's blocking C reads; that is now fixed by killing the child instead.

    pip install metocean-api
    python -m offsim.worlds.metocean_api fetch --world bergen-ncs \
        --point 3.0,60.6 --years 2000-2023 --season DJF

Expect 1 to 2.5 hours, unmeasured. A resumed run prints `RESUMING: n/144 already on disk and valid`; a fresh
one prints `STARTING: 0/144`. If it dies, run it again — that is the point of the design. Report the actual
wall time per unit, because nobody has measured it.

The point 3.0 E, 60.6 N is an assumption (open sea inside the bergen-ncs box). If you have a better reason
for another over-water cell, use it and say why in the report.

Five things A3 could not prove offline. Check each on the first real file and write the answer in the report:
  1. do the live monthly files have the structure the fixtures assume (rotated grid `rlat`/`rlon` for waves,
     `height`/`y`/`x` for wind, 2D `longitude`/`latitude`)?
  2. are they hourly and whole-month? (a gap fails loudly with a missing-hours count — do not suppress it)
  3. do the months Dec 2000 through Feb 2024 all exist on the server?
  4. time per unit.
  5. which direction convention `thq` uses. A wrong convention silently rotates every sea state.

Then publish the result as a GitHub release and confirm
`python -m offsim.worlds.fetch_world --pull bergen-ncs` retrieves it, so the cloud session can use it too.

Gribkovskaia & Slettemark's model contains no weather. Winter on the NCS is the entire reason helicopter
planning is hard. Our `air` engine does have weather and operability limits. So, once N4.1 lands:

> Take the paper's optimal weekly flight program. Replay it against the 24 real winters.

shelf, it is a ranked gap, and it is the first thing this machine will have produced that is genuinely new
rather than reproduced. Do not tune anything to make the number look good. A boring result honestly measured
is a result; a tuned one is nothing.
